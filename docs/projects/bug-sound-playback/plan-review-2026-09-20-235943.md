## Objections (5)

**[high] · correctness-and-coverage · step 2** — The plan does not define how each catalog asset URL reaches the playback engine, so adding `src` fields can leave runtime playback disconnected from the tested metadata.
  Why: `AppController.activate` currently discards the catalog entry after reading its ID, while `AudioEngine.play` accepts only an ID. Catalog/file tests could pass while production hardcodes or misroutes a different URL.
  Fix: Pass an explicit `{ id, src }` contract into the engine, assert the media factory receives that exact `src`, and cover all thirteen mappings.
  Disposition: fixed — step 2 now names and tests the catalog → controller → engine source contract.

**[high] · correctness-and-coverage · step 2** — A short gallop recording has no specified mechanism or elapsed-time test guaranteeing a thirty-second one-shot.
  Why: Native end would stop too early, while unconditional looping would never stop; stale timers could also mutate a replacement run.
  Fix: Use an injectable thirty-second scheduler over the loopable recording and assert 29,999/30,000 ms plus replay, toggle, release, and stale-deadline behavior.
  Disposition: fixed — step 2 now requires the scheduler and exact clock-controlled cases.

**[high] · correctness-and-coverage · step 2** — Gesture-safe media playback is not guaranteed while the existing asynchronous Web Audio resume remains ahead of effect creation.
  Why: Awaiting `AudioContext.resume()` can move `HTMLMediaElement.play()` outside transient user activation on restrictive mobile browsers.
  Fix: Bypass Web Audio for recordings, invoke media playback synchronously in the click stack, and retain AudioContext setup only for microphone monitoring.
  Disposition: fixed — approach and step 2 now make this ordering explicit and test it with a pending context resume.

**[medium] · correctness-and-coverage · steps 3 and 5** — Transport checks do not re-test semantic fidelity for every label.
  Why: A swapped or merely loadable asset would pass 200/playback assertions while preserving the reported defect.
  Fix: Execute and record a thirteen-row recognizability and phone-loudness matrix before merge and after deployment.
  Disposition: fixed — step 5 now treats the labeled listening matrix as a release gate alongside transport checks.

**[low] · simplicity-and-rollback · step 4** — Restoring source files in the implementation worktree for the revert-check risks a hybrid tree and duplicates the recorded red state.
  Why: New tests and assets would remain while only source files are restored, and a failed restore could leave stale code.
  Fix: Run the new regression test against the test-only commit in an isolated temporary worktree.
  Disposition: fixed — step 4 now uses an isolated worktree and never mutates the implementation tree.

Convention-fit found no objections.
