## Objections (2)

**[high] · correctness-and-coverage · Step 4** — Step 4 cannot manually dispatch the newly added Pages workflow from this feature branch before merge.
  Why: GitHub only accepts `workflow_dispatch` for workflows present on the default branch. Because this repository currently has no Pages workflow on `main`, the planned pre-merge feature-branch deployment would not start, so the app could not become live at the stated gate.
  Fix: Either merge the workflow before deploying, land a minimal dispatchable workflow on `main` first, or temporarily add a push trigger for this exact feature branch and remove it before merge.
  Disposition: fixed — Step 4 now uses a temporary exact-branch push trigger for pre-merge deployment and removes it only after the final live smoke test.

**[medium] · correctness-and-coverage · Steps 2–3** — The gallop pad and its loop control do not have a defined shared state transition when one is used while the other is active.
  Why: The plan combined per-sound active-handle replacement with separate one-shot and loop controls. Tapping the main gallop pad while looping could replace the loop source without clearing the loop-active UI, while toggling loop during a one-shot could produce the inverse inconsistency.
  Fix: Specify and test a gallop state machine: starting either mode stops the other, loop UI reflects the actual active source, and page changes, repeated taps, and disposal preserve or clear that state deterministically.
  Disposition: fixed — Steps 2–3 now define one shared gallop mode, derive UI state from it, and require transition coverage.
